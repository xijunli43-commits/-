# Windows 用户：GitHub 云端构建

## 上传与运行

1. 在 GitHub 新建仓库，建议 Private（私有）。私有仓库的 macOS 构建消耗 Actions 额度，超额费用以账户页面为准，不要未经核对开启付费超额。
2. 把本工程文件上传至仓库根目录：project.yml、PhoneRank、PhoneRankTests、.github 等直接位于根目录。不要把整套工程再套一层 PhoneRank 目录，也不要只上传 ZIP 文件。
3. 不上传 backend/data、backend/.venv、日志或本机数据库；交付 ZIP 已排除这些内容。内置 catalog.json 是应用需要的种子数据。
4. 仓库 Actions → Build iPhone IPA → Run workflow。若 GitHub 要求启用 Actions，先按页面提示启用。
5. 等待运行成功，进入该次运行页面的 Artifacts，下载 PhoneRank-iPhone-运行号，解压取得 PhoneRank-unsigned.ipa。
6. 此文件还未签名，不能直接在 Safari 点开安装。用 Windows 上的 AltServer/AltStore 和自己的免费 Apple 账号完成本地签名安装；无需把 Apple 密码交给 GitHub。

## 构建内容

使用 macos-26 runner、XcodeGen 生成工程，先执行现有 XCTest，测试通过后编译 Release 真机 ARM 应用，再按 Payload/*.app 的结构打包 IPA。编译/测试日志和 xcresult 即使失败也尽可能保留，产物有效期 7 天。无需 Apple 签名证书、Secrets 或付费开发者账号进行这一步。

这不是 App Store/TestFlight 包。免费账号的安装有效期有限，需要定期刷新。手机系统必须为 iOS 26+。第三方本地安装方式的兼容性需实机核验；成功编译不等于已成功安装。

## 失败处理

在 Actions 页面点击失败的步骤，查看红色错误及 Artifacts 中的日志。测试失败时不会继续打包，不隐藏错误。若 runner 不再包含 iOS 26 模拟器，需根据 GitHub 官方镜像更新筛选条件；若 Xcode 编译报错，按实际报错修正 Swift 源码后再提交。此环境是 Windows，目前未真正执行云端编译，不能保证首轮构建通过。

## 参考与复用

复用 [GitHub macOS runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)、[镜像软件清单](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md)、[checkout](https://github.com/actions/checkout)、[upload-artifact](https://github.com/actions/upload-artifact) 及既有 XcodeGen/XCTest。两个 GitHub 官方 Actions 均为 MIT；使用 v4 主版本，后续可固定到审核过的 commit SHA。工作流只有 contents:read 权限，不部署服务器、不上传 Apple 凭据。

本地没有既有 CI 或 Git remote，GitHub CLI 不可用；已查官方文档及现有源码。自定义部分只是本项目的测试、设备构建与未签名 IPA 打包步骤，不增加运行时依赖。
